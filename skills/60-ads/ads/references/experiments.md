# Design a test that can change the decision

Use for campaign, creative, bidding, audience or destination tests. Read the
selected platform topic for actual supported operations. A supplied dataset can
support a design without an account connection or new experiment creation.

Record the observed problem, falsifiable hypothesis, control, changed unit,
held conditions, primary business metric, acceptable loss, guardrail metrics,
conversion lag, allocation method and stopping/analysis rule. State what
improvement would be worth acting on. Use actual baseline traffic and event
rates when calculating sample and duration; label assumptions.

## Choose the comparison honestly

- A native platform experiment can provide a defined allocation mechanism;
  inspect the actual experiment type and account eligibility.
- Ads in one optimized ad set or adaptive RSA assets are not randomized equal
  exposure. Report an observational comparison with its delivery differences.
- A before/after landing-page or SEO change is exposed to seasonality,
  promotions and search-engine changes. Record those alternative explanations.
- An AI-answer comparison needs stable prompts, engine, locale and repeated
  captures. A single answer cannot establish a treatment effect.

Match scope to the question. An entire concept can be one test unit, but then a
win does not isolate the headline as its cause. Choose a fixed-horizon,
sequential or other appropriate analysis before observing results; do not keep
extending a finished test until it becomes significant. Interpret uncertainty
and practical effect together. Inconclusive is not equivalent or a winner.

## Prepare, execute and close

Use the user's existing authorization for exact targets and spend. Prepare
reviewable variants/configuration and validate through the selected platform
where supported. Create paused objects when delivery activation is outside
scope. Native Google experiment setup, arms and scheduling are separate steps;
an experiment definition is not a running test. The current Meta directory does
not establish a native randomized experiment tool; do not call an ordinary
duplicate a native split test.

Preserve original and created IDs, operation identities and first business
responses. Repair a definite pre-submission error within the original intent;
resolve unknown writes through the original operation and exact resource reads.
Never create a replacement to recover a lost acknowledgement.

At review, check measurement validity, maturity, allocation/sample and guardrail
outcomes before declaring a winner. Return effect and uncertainty, what the
design can actually establish, the chosen next action and a retained control or
recovery plan. Hand observed creative results to benchmark-to-brief for the
next production slate; changing spend remains an Ads action.
