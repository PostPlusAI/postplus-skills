# SEO and AI search visibility

Improve discovery and qualified customer outcomes for the user's website.
GEO means visibility in generative search answers here, not ad geography.
Reuse approved product facts, existing reports and the actual site or repository.
A supplied export or content review needs no new connection or paid collection.

## Select the task

| User outcome | Read when needed |
| --- | --- |
| Find valuable queries, group intent, identify the page serving each need | [Search demand](references/search-demand.md) |
| Diagnose or fix crawl, indexing, canonical, sitemap, internal-link or rendering issues | [Technical SEO](references/technical-seo.md) |
| Choose content, improve a page, plan comparisons or evaluate templated pages | [Content planning](references/content-planning.md) |
| Measure citations and recommendations, inspect AI claims, or correct source facts | [AI visibility](references/ai-visibility.md) |
| Decide how paid evidence should inform organic content or the next bounded test | [Paid and organic planning](references/paid-organic.md) |

Load only the relevant references. Establish the site, market/language, business
outcome and observation period where they affect the decision. Keep a search
query, bid keyword, AI prompt, page URL and customer outcome distinct.

## Use evidence from its owning task

Use the available Measurement skill for Search Console and GA4 report selection,
scope, pagination and event diagnostics. Use Ads for search-term evidence,
keyword planning, bidding goals or any campaign change. The agent can combine
their guidance within the same task; do not make the user relay results.
Use current registered tools and schemas for connected reads. A connection to
Ads does not grant Search Console or website-edit access.

Read real pages or source files through the host's available authorized tools.
Do not assume a crawler, competitor-ranking database or multi-engine AI monitor
exists. GSC describes the selected site's observed search performance; it does
not provide competitors' complete rankings or an individual's search journey.

## Repair confirmed problems

For a requested fix, inspect the implementation that owns the defect, preserve
the baseline, make the smallest justified change, and run the relevant local or
preview checks. Routine reversible edits within the task need no extra approval.
Use the repair and acceptance procedures in the selected reference; do not stop
at advice when authorized editing is available.

Website publication, redirects affecting existing traffic, indexing-control
changes and advertising spend follow the user's existing authorization. Prepare
the exact patch and its tests before requesting any additional release decision.
If no authorized editing surface is available, deliver an applicable patch or
precise edit instructions and identify the missing edit/publish operation.
Do not describe a prepared repair as applied or a local check as reindexing.

## Deliver and learn

Return the observed issue/opportunity, source and scope, chosen action, actual
patch or configuration result, acceptance evidence and next observation needed.
Separate verified facts, hypotheses and unavailable evidence. Save useful raw
results and decisions in an existing project or supported artifact destination;
do not create a second product-truth file or assume cross-session storage.

Judge search traffic, qualified outcomes, citations, recommendations and answer
accuracy separately. Do not promise rankings or infer that ad spend improves
organic position. A tracking fix belongs to Measurement; a paid-object change
belongs to Ads even when discovered during this task.
