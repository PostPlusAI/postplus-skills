# Choose and improve useful search content

Start from the buyer task and the existing page inventory. Use
[search demand](search-demand.md) to select the need. Inspect current search
results and actual customer questions before committing to a new piece. State
what the page adds: first-hand product evidence, a working example, original
data, a useful comparison or a clearer supported answer. Do not manufacture
facts to make a page seem distinctive.

Deliver a brief with the target task/market, intended URL or current page,
distinct value, approved facts and sources, outline, proof, next action, links
from relevant existing pages and acceptance conditions. The brief can support
an actual local edit when requested; it is not permission to publish.

## Common improvements

- If the page fails to answer the query, rewrite the relevant introduction and
  sections using confirmed product capabilities and the customer's task. Keep
  material limitations visible. Verify that the next action actually exists.
- If an ad promises a comparison but the destination only requests a demo,
  produce the comparison or revise the approved ad promise through Ads. Do not
  make up competitor shortcomings. Preserve comparison sources and dates.
- If pricing/features are stale, trace the approved owner and update the page,
  structured facts and related affected copy together. A preferred new price
  is not a confirmed fact; ask when the authoritative sources conflict.
- If content exists but is hard to find, add relevant contextual links through
  the current templates/content. Check destination, accessibility and rendered
  navigation. Do not impose an arbitrary number of links per page.
- If many templated pages are proposed, require a distinct useful answer and
  reliable data for each selected pattern. Start with representative pages and
  inspect quality and indexing evidence before expanding. Do not mass-create
  city or industry substitutions to manipulate rankings.

Preserve one owning source for product facts; content can express them for a
particular audience without redefining them. An advertising landing page and
an organic guide may serve different tasks and indexing policies. Choose their
relationship from evidence, rather than force one universal page.

## Acceptance

For a local change, inspect the diff, build/render the affected route and check
the factual claims, mobile reading order, links and CTA. Reuse existing site
checks. Record title, destination and content changes so later results can be
interpreted. Do not attribute an increase to one sentence when other variables
changed. Use a mature comparable window for search and qualified outcomes;
seasonality, promotions and engine changes remain alternative explanations.

Deliver the edited content/patch and evidence, not only recommendations, when
the user requested a repair and authorized editing is available. A cloud-only
session without website access should deliver the applicable edit and name the
missing write surface. Preserve the previous source version for rollback.
