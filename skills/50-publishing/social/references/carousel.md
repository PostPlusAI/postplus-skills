# Carousel

A carousel is a sequence of panels, not a shortcut for publishing the same
article in images. Use it when the reader gains something by moving through
steps, a comparison, a demonstration, or an argument.

Choose a narrative suited to the source: question → answer → worked example;
problem → diagnosis → alternative; or task → numbered steps → result. Give
each panel one job and specify its claim, visual proof, and transition. The
cover must state a real promise; any count on it must match the actual panels.
The final panel should close the argument and ask for one useful next action.
Keep text legible at phone size, apply a coherent visual system, and provide
alt text or accessible caption detail when supported. A pretty mockup is not
evidence of a result. Do not invent screenshots, customer quotes, statistics,
or platform-specific limits.

Deliver a panel-by-panel outline with source for each material claim, asset
needed, caption, and outstanding permissions. If the user supplies images,
inspect dimensions and rights before choosing a publication route. The current
Instagram catalog exposes carousel container fields and separate publication,
but actual child processing and platform acceptance need evidence; do not
substitute a single-image example. Pinterest image, video, and carousel inputs
have different media shapes. Read [Instagram/Facebook](instagram-facebook.md)
or [Reddit/Pinterest](reddit-pinterest.md) and the current `channels tools show`
schema before constructing media input. A LinkedIn PDF/document carousel is
not promised by the basic text-post example; treat it as a separate capability
check. Creating artwork or editing a video uses the existing media Skills when
needed and can incur credits.

For review, compare panels against the original promise and ask whether each
one advances it. For performance, use the platform metric actually returned
for the post; do not infer completion, saves, or conversions from public likes.
